01 · Case study

RepoViz: a codebase map that tells you where to start

RepoViz turns any GitHub repository into an interactive map of its files and the imports between them. I designed and built the first version, then used it, found where it failed, and redesigned it.

Role
UI design & frontend; the redesign
Team
2 people · GDSC Open Projects
Tools
Figma, React, React Flow, Claude
Timeline
Summer 2026 · redesign Nov 2026
Open Figma file ↗ Clickable prototype ↗

The problem with v1

I tested my own first version on Flask’s source code, a small, well-known project. The graph became unreadable almost immediately.

24files
6,975lines of code
92imports drawn as animated dashed lines
  • Every arrow was animated and dashed, so even a small repo turned into spaghetti.
  • File cards showed full paths in tiny text, unreadable at the default zoom.
  • A flat layout hid the project’s folder structure.
  • It showed the structure but never answered the question people actually had: where do I start reading?

What I changed

  1. Quiet by default, focus on demandEdges stay calm and static. Hover a file and only its connections light up: violet for what it imports, teal for what uses it. Everything else fades.
  2. Folders as containersFiles sit inside labelled folder groups, so the architecture is visible before you read a single file name.
  3. An overview that answers “where do I start?”Entry points (files nothing else imports), the most-imported core files, and the largest files, each one click away.
  4. Readable file cardsFile name in bold monospace, line count underneath, a colour stripe for the language that matches every other view.
  5. AI summaries you can scanPurpose, Key parts and Role in the project instead of one block of text, with a plain-language error and a retry button when the AI fails.
  6. Designed edge casesAn empty state with one-click example repos, loading states, and search on the / key.

Design system

To keep the redesign consistent, I documented it in Figma: colour tokens for surfaces, text and meaning (imports, used by, warnings), a fixed colour per language, a type scale pairing Inter for interface text with JetBrains Mono for file names and numbers, and 10 components with variants, including a file card in 2 languages × 6 states.

The full before/after with numbered notes is below; click any image to enlarge it.

What I’d do next

Run a quick test with 5 students opening an unfamiliar repo, and time how long it takes each of them to find the entry point in v1 and in v2.

02 · Case study

ContractGuard: a pitch deck that leads with the money

ContractGuard is an AI system that catches billing leaks in Indian construction contracts, built by a 3-person team at the Kaya AI × IIT India Hackathon 2026. I built its mismatch-detection logic and the pitch deck, then redesigned the deck.

Role
Detection logic & deck design
Team
3 people · Track 3: Procurement
Tools
Figma, Google Slides, Claude
Format
9 slides · 16:9
Open Figma file ↗

The problem with v1

The original deck told the right story, but judges had to read every word to find it.

  • Mostly small text on a plain background; every slide looked the same.
  • The strongest fact, ₹1,96,650 of leakage caught in the demo, was buried on slide 7 of 10.
  • No visual link between the deck and the product the team had built.

What I changed

  1. Lead with the moneyThe total caught became a stamp on the title slide and the hero number on the results slide.
  2. One idea per slideEach headline states the takeaway, so a judge skimming only the headlines still gets the pitch.
  3. Show, don’t listThe three leak types became cards with real examples, the process a 4-step timeline, and the results bars that compare each error’s size.
  4. An identity borrowed from the productPaper, ink and stamp-red colours from the dashboard, a serif for headlines and a monospace for rupee amounts, so deck and product feel like one brand.
  5. Cut the fillerThe agenda slide went; 10 slides became 9.
